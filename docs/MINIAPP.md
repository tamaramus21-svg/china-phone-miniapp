# Mini App: запуск, безопасность и публикация

Магазин имеет графический интерфейс React + TypeScript + Vite. Тот же Python-процесс обслуживает собранный frontend, HTTP API, aiogram polling и очередь уведомлений. Вся бизнес-информация остаётся в существующей SQLite. Админ-панель `/admin` сохранена в Telegram.

## Что уже работает

- Главная с иллюстрацией, поиском, категориями по реальным брендам и товарами. Популярность определяется сохранёнными заказами; если заказов нет, показываются новые поступления. Демонстрационные товары в рабочую базу не добавляются.
- Каталог с пагинацией, поиском, фильтрами бренда/цены/наличия; карточка с фотографиями, вариантами, характеристиками и состоянием склада.
- Серверный расчёт цены, отдельный экран проверки выбора, подтверждение заказа, номер/статус, готовое сообщение продавцу, история собственных заказов.
- Нижняя навигация, темы Telegram, безопасные отступы, системная кнопка назад, защита от двойных нажатий и повторов после сетевых ошибок.
- Кнопки `/start` используют `WebAppInfo`, когда настроен `WEBAPP_URL`. Все основные пункты меню открывают нужный экран Mini App. Старые текстовые обработчики и функции администратора остаются доступны.

## Переменные окружения

Корневая `.env` остаётся только на машине/сервере. Существующий токен сохранён; повторно создавать этот файл не нужно.

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Действительный токен, только backend |
| `ADMIN_ID` | `8543142739`; другая конфигурация отклоняется |
| `WEBAPP_URL` | Публичный URL frontend вида `https://shop.example.com`, пока пустой |
| `ADMIN_USERNAME` | Реальный username продавца без @; необязательно |
| `DATABASE_PATH` | По умолчанию `data/shop.sqlite3`; Docker использует `/app/data/shop.sqlite3` |
| `SHOP_NAME` | Название по умолчанию; сохранённая настройка SQLite имеет приоритет |
| `HTTP_HOST` | Локально `127.0.0.1`; в Docker `0.0.0.0` |
| `HTTP_PORT` | Локально `8080` |
| `INIT_DATA_MAX_AGE` | Срок действия Telegram-авторизации в секундах, по умолчанию `3600` |
| `SHOP_DOMAIN` | Только для Docker/Caddy: реальный домен без протокола, например `shop.example.com` |

`frontend/.env.example` содержит только необязательный публичный `VITE_API_ORIGIN` — HTTPS origin отдельного backend. Он попадает в bundle и **не должен содержать токен, пароль или `initData`**. Рекомендуемый Docker-вариант обслуживает всё на одном домене и не требует этой переменной. Если frontend на другом хостинге, его URL указывается в `WEBAPP_URL` backend; CORS разрешает только соответствующий origin.

## Локальная разработка (PowerShell)

Из корня проекта, Python 3.11+ и Node.js 24+:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
# Только если .env ещё нет:
# Copy-Item .env.example .env
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
.\.venv\Scripts\python.exe main.py
```

Backend и production frontend: `http://127.0.0.1:8080`. Для HMR в другом терминале: `pnpm --dir frontend dev`; frontend `http://127.0.0.1:5173` проксирует `/api` и `/media` локальному backend.

Если polling уже работает и нужен только локальный просмотр HTTP, используйте `python main.py --web-only`. Этот режим не запускает polling и фоновые повторы уведомлений. Не запускайте два процесса polling с одним токеном. Не запускайте второй HTTP-сервер на занятом порту.

Обычный браузер без Telegram показывает предложение открыть приложение через бота. Поддельные `initDataUnsafe` и ID из адреса не дают доступа к API. Никакого небезопасного dev-login в приложении нет. Локальный HTTP предназначен для разработки и не открывается как production Mini App в Telegram. Автоматические UI-тесты используют изолированные подставные ответы; эти данные не попадают в рабочую SQLite.

## Публикация из GitHub на сервер с HTTPS

GitHub хранит исходники и запускает проверки; сам магазин нужно разместить на VPS/хостинге, поддерживающем постоянно работающий Python и постоянный диск SQLite. GitHub Pages не запускает Python и [не допускает размещение интернет-магазинов](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits). Публикация репозитория не означает, что Mini App уже доступен в Telegram.

1. Подготовьте Linux-сервер с Docker Engine и Docker Compose. Нужны входящие 80/443, исходящий HTTPS к Telegram и постоянное место для базы. Домен направьте A/AAAA-записью на сервер; не указывайте AAAA, если IPv6 не настроен.
2. Склонируйте репозиторий. Остановите старый polling-процесс перед переносом. Сделайте согласованную резервную копию:

   ```powershell
   .\.venv\Scripts\python.exe scripts/backup.py
   ```

3. Передайте актуальную `.env` на сервер приватным способом. Передайте копию базы из `backups/` как `data/shop.sqlite3`; не отправляйте базу и секреты в GitHub. Копия создаётся штатным SQLite backup API и включает WAL-транзакции.
4. В `.env` сервера задайте `SHOP_DOMAIN=ваш.домен` и `WEBAPP_URL=https://ваш.домен`, сохранив действительный токен. Подготовьте каталоги и права пользователя контейнера:

   ```sh
   mkdir -p data logs
   sudo chown -R 10001:10001 data logs
   chmod 600 .env
   docker compose up -d --build
   docker compose ps
   docker compose logs --tail=40 shop
   ```

5. Caddy получает и обновляет доверенный сертификат. Проверьте `https://ваш.домен/healthz` (`{"status":"ok"}`) и загрузку главной. Неправильный DNS или закрытые порты мешают выпуску сертификата.
6. В Telegram отправьте боту `/start` заново: новая кнопка «🛍 Открыть магазин» открывает Mini App, меню бота также переключается на Web App. У старых сообщений старая клавиатура остаётся до нового `/start`.
7. При желании настройте Main Mini App в BotFather: `/mybots` → ваш бот → Bot Settings → Configure Mini App → Enable Mini App и укажите этот HTTPS URL. Для inline-кнопки и меню URL уже задаётся самим ботом.
8. Администратор отправляет `/start`, затем `/admin`, добавляет первый реальный товар. Со второго аккаунта проверьте фото, выбор вариантов, подтверждение, получение заказа и смену статуса. Это отдельная живая проверка, не заменяемая локальными тестами.

`docker compose down` сохраняет bind-mounted `data`/`logs` и тома сертификатов. Для обновления: приватная резервная копия → `git pull` → `docker compose up -d --build`. Схема обновляется с версии 1 до 2 без удаления продуктов, настроек и заказов.

## API

Авторизованные запросы передают `Authorization: tma <Telegram.WebApp.initData>`.

| Метод | Адрес | Назначение |
| --- | --- | --- |
| GET | `/healthz` | Проверка процесса без секретов |
| GET | `/api/me` | Пользователь из проверенной подписи |
| GET | `/api/shop` | Название, информация, бренды, настроенный продавец |
| GET | `/api/products` | `page`, `query`, `brand`, `minimum`, `maximum`, `available`, `sort` |
| GET | `/api/products/{id}` | Актуальные характеристики, цвета/память, комбинации и URL фото |
| POST | `/api/products/{id}/price` | `color`, `memory`, `revision`; расчёт сервером |
| POST | `/api/quotes` | `product_id`, `revision`, `color`, `memory`, `request_key` |
| POST | `/api/orders` | Только `quote_token` из ответа `/quotes` |
| GET | `/api/orders?page=0` | Только заказы текущего пользователя |
| GET | `/api/orders/{id}` | Свой заказ, снимок и готовое сообщение |
| GET | `/api/admin/stats` | Защищённая статистика |
| GET | `/api/admin/orders` | Защищённый список всех заказов |
| PATCH | `/api/admin/orders/{id}/status` | Защищённая смена статуса |
| GET | `/media/products/{id}/{index}` | Публичные фото реального товара через proxy |

Фотографии публичны как часть витрины, но путь Telegram с токеном не отдаётся клиенту. Нельзя запросить произвольный `file_id`: сервер берёт его только из товара в SQLite. Есть ограничение параллельных скачиваний и кеш на 32 МБ. Удалённый товар не выдаёт фото по новому запросу.

Проверка HMAC соответствует [официальному алгоритму Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app). Дублирующиеся поля, истёкшая подпись, время из будущего и другой токен отклоняются. ID покупателя не принимается из тела. Подпись проверяется на каждом API-запросе; `initDataUnsafe` не используется. После истечения сессии откройте Mini App заново.

`request_key` обязателен: повторы запроса выбора с тем же ключом возвращают один `quote_token`. Смена данных при том же ключе отклоняется. Подтверждение транзакционно возвращает один заказ для одного `quote_token`, даже после перезапуска. Изменение товара требует повторной проверки карточки. Клиентская цена игнорироваться не может: неизвестные поля, включая `price`/`user_id`, отклоняются.

Тела запросов ограничены 32 КБ, `initData` — 16 КБ. Действуют лимиты запросов по подтверждённому ID и peer-адресу; текст ошибок не раскрывает токен или URL Telegram. Если перед backend стоит reverse proxy, приложение не доверяет произвольному `X-Forwarded-For`; общий peer-лимит дополняется персональным. Для высокой нагрузки лимиты/прокси нужно отдельно настраивать под доверенную сеть.

## Проверки и ограничения

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m compileall -q main.py config.py bot database utils webapp tests
.\.venv\Scripts\python.exe -m pip check
pnpm --dir frontend build
pnpm --dir frontend exec playwright install chromium
pnpm --dir frontend test:e2e
```

GitHub Actions проверяет backend, сборку frontend, пять браузерных сценариев и сборку Docker image; frontend-сборка доступна как artifact. Токен для CI не нужен. Docker-сборка проверяется в CI, если локального Docker нет. Локальные проверки не означают успешный деплой на VPS или проверку настоящего Telegram-клиента.

Один заказ — один смартфон; экран «Выбор» хранит текущее оформление, это не многотоварная корзина. Остаток не резервируется автоматически, его подтверждает продавец. Начатые админ-диалоги остаются в памяти, как в исходном боте. Доставка уведомлений гарантирует сохранение очереди, но при аварии в момент ответа Telegram уведомление может прийти повторно. История и данные пользователей в публичный репозиторий не включаются.
